The Enterprise SE Evaluation Disparity

Standard automated program repair (APR) literature evaluates overwhelmingly on lightweight, single-threaded Java benchmarks (e.g., Defects4J, QuixBugs). These suites lack the multi-gigabyte asset pipelines, physics loop non-determinism, and cross-language interop crashes inherent to modern game engines.

Mathematical Justification for OSSGameBench

With substantial statistical heterogeneity (\(I^2 = 89.1\%\)) and a +50.0% domain gap, the Benchmarking Need Index (\(B = I^2 \times \Delta_{\text{Disparity}} = 0.4455\)) empirically proves that benchmark variability dominates tool performance variance, directly justifying OSSGameBench as a standardized game engine testbed.
