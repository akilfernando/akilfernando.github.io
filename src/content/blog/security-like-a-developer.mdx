I came to security through software development. Having built back ends, authentication flows, and data models helps me understand how security controls affect an application and where they might cause problems.

## Identity in the applications I build

When I connect an internal app to Entra ID single sign-on, I can use the organization's existing identity controls instead of maintaining a separate account system. That includes MFA and the processes for granting and removing access.

Because I work on both the application and identity management, I can check how those decisions fit together.

## Automating routine checks

A security reporting tool I inherited uses browser automation to collect information that would otherwise need to be checked manually. A language model helps summarize the results for review.

Automating collection reduces the repetitive work. People still need to review the findings and decide which issues need attention.

## What the two roles have in common

Both roles involve understanding how systems behave when something goes wrong. In development, that might mean handling unexpected input or a dropped connection. In security, it might mean checking whether someone still has access after changing roles.

Working across both areas helps me consider those questions while building and maintaining internal tools.
